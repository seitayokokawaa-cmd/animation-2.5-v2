# ADR 0009 — Procedural SFX synthesis instead of vendored sample files

## Status

Accepted (M9.2).

## Context

The plan calls for a CC0 SFX library (whoosh, pop, slam, boink, explosion,
crowd, quill, ding, drumroll) with a license manifest. Vendoring recorded
samples has three problems here:

1. **Provenance risk.** "CC0" packs frequently contain mislabeled files;
   we cannot audit recordings we did not make.
2. **Binary blobs.** The repo has no binary assets besides fonts and
   geodata; audio samples are the classic source of repository bloat and
   un-reviewable diffs.
3. **Determinism is free if we synthesize.** The engine already has a
   seeded PCG32; cartoon SFX for this genre (pops, boinks, thuds, swooshes)
   are square-one DSP — envelopes over sines and filtered noise — and the
   exaggerated synthetic character *is* the genre sound.

## Decision

SFX are **synthesized in-engine** by pure functions in
`@motionforge/render` (`sfx.ts`): `sfxSamples(name)` → 48 kHz mono
Float32 samples, deterministic per name (noise comes from PCG32 streams
seeded by the cue name). The audio bus (M9.1) names cues; the mixer places
these synthesized samples. No sample files are vendored.

`assets/audio/ATTRIBUTION.md` records that all SFX output is original,
procedurally generated by this repository and dedicated to the public
domain (CC0), which satisfies the license-manifest requirement with zero
provenance risk.

## Consequences

- Byte-determinism of the mix holds by construction; no golden WAV assets.
- Sound design tuning is code review, not file swaps.
- Recorded samples can still be added later for richness: the manifest and
  the cue-name indirection already accommodate a hybrid library.
